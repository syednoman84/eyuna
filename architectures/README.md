# Architectures

## Purpose

This directory holds reference architecture patterns for AI systems and solutions — reusable, validated architectural approaches that consultants can adapt to a specific client context rather than designing from scratch on every engagement.

## Contents

This directory does not yet contain architecture pattern content. It is scaffolded during Release 1.0 (Foundation) so the category exists ahead of the content itself; population is not tied to a single named release and will proceed as patterns are validated through engagement and case-study work (see [ROADMAP.md](../ROADMAP.md)). When populated, it will contain:

- A reference architecture documentation standard (problem context, pattern, trade-offs, when to use / avoid)
- Patterns organized by problem domain (e.g., retrieval-augmented generation, agentic workflows, data pipelines, evaluation and observability)

## How This Fits Into Eyuna

Architectures give the [ACM Methodology](../docs/acm-methodology.md)'s design phase concrete technical options to draw from. They are referenced by playbooks ([`../playbooks/`](../playbooks/README.md)) as recommended approaches for a given industry scenario, implemented in starter projects ([`../starter-projects/`](../starter-projects/README.md)) and reusable components ([`../reusable-components/`](../reusable-components/README.md)), and validated through case studies ([`../case-studies/`](../case-studies/README.md)).
