# Starter Projects

## Purpose

This directory holds bootstrappable starting points for new engagements — minimal, opinionated project scaffolds that let a consulting team begin an engagement from a known-good baseline instead of an empty repository.

## Contents

This directory does not yet contain starter-project content. It is scaffolded during Release 1.0 (Foundation) so the category exists ahead of the content itself; population will follow once reference architectures ([`../architectures/`](../architectures/README.md)) and templates ([`../templates/`](../templates/README.md)) mature (see [ROADMAP.md](../ROADMAP.md)). When populated, it will contain:

- A starter-project standard describing what every starter project must include (documentation, structure, setup instructions)
- Individual starter projects, each aligned to a specific architecture pattern or engagement scenario

## How This Fits Into Eyuna

Starter projects are where the [ACM Methodology](../docs/acm-methodology.md), architecture patterns ([`../architectures/`](../architectures/README.md)), reusable components ([`../reusable-components/`](../reusable-components/README.md)), and templates ([`../templates/`](../templates/README.md)) come together into something a team can literally clone and start working from. They are the most concrete, hands-on layer of the framework — a bridge from methodology and reference material to a running engagement.
