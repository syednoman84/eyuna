# Tools

## Purpose

This directory holds internal tooling that supports the consulting workflow itself — utilities consultants use while running engagements, as distinct from the deliverables ([`../templates/`](../templates/README.md)) or reusable technical building blocks ([`../reusable-components/`](../reusable-components/README.md)) those engagements produce.

## Contents

This directory does not yet contain tooling content. It is scaffolded during Release 1.0 (Foundation) so the category exists ahead of the content itself; population will follow as recurring workflow needs are identified (see [ROADMAP.md](../ROADMAP.md)). When populated, it will contain:

- A tool documentation standard (purpose, usage, dependencies)
- Individual internal tools supporting engagement work (e.g., prompt evaluation helpers, documentation generators, engagement checklists)

## How This Fits Into Eyuna

Tools exist to make the [ACM Methodology](../docs/acm-methodology.md) easier to execute in practice — they support consultants directly rather than producing client-facing artifacts. This distinguishes `tools/` from [`../scripts/`](../scripts/README.md), which automates maintenance of the Eyuna repository itself rather than engagement work.
