# Personas

## Purpose

This directory holds the consulting personas used consistently across Eyuna engagements — both internal roles (e.g., engagement lead, AI architect, delivery consultant) and client-facing archetypes (e.g., executive sponsor, technical stakeholder, end user). Personas give every engagement a shared, reusable vocabulary for "who is involved and what do they need," instead of re-defining roles from scratch each time.

## Contents

This directory is currently empty of persona content — it is scaffolded ahead of Release 2.0 (Consulting Personas), per [ROADMAP.md](../ROADMAP.md). When populated, it will contain:

- A persona template defining the standard fields every persona documents (goals, concerns, decision authority, communication style, etc.)
- Internal personas used to staff and structure engagements
- Client-facing personas used to guide discovery, communication, and solution design

## How This Fits Into Eyuna

Personas are one of the primary inputs to the [ACM Methodology](../docs/acm-methodology.md): each phase of an engagement references the personas involved to determine what prompts ([`../prompts/`](../prompts/README.md)) and templates ([`../templates/`](../templates/README.md)) are relevant. Playbooks ([`../playbooks/`](../playbooks/README.md)) and case studies ([`../case-studies/`](../case-studies/README.md)) will reference personas by name rather than re-describing roles inline, keeping engagement documentation consistent across the framework.
