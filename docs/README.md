# Docs

## Purpose

This directory holds Eyuna's foundational documents — the governing texts that define what Eyuna is, how it works, and how decisions within it are made. Everything else in the repository (personas, prompts, templates, playbooks, case studies, architectures) is built on top of the principles and methodology defined here.

## Contents

| Document | Description |
|---|---|
| [`constitution.md`](constitution.md) | The foundational charter defining Eyuna's purpose, scope, and operating rules. |
| [`acm-methodology.md`](acm-methodology.md) | The AI Consulting Methodology (ACM) — Eyuna's core engagement methodology. |
| [`consulting-principles.md`](consulting-principles.md) | The principles that guide how consulting work is approached and delivered. |
| [`governance.md`](governance.md) | How Eyuna is governed: decision-making, ownership, and change management. |
| [`glossary.md`](glossary.md) | Shared definitions of terms used consistently across the repository. |

All five documents are currently placeholders — see [PROJECT_STATUS.md](../PROJECT_STATUS.md) for authoring status.

## How This Fits Into Eyuna

`docs/` is the constitutional layer of Eyuna. Personas ([`../personas/`](../personas/README.md)), prompts ([`../prompts/`](../prompts/README.md)), templates ([`../templates/`](../templates/README.md)), and playbooks ([`../playbooks/`](../playbooks/README.md)) are all expected to be consistent with the methodology and principles defined here. When those documents are authored, other directories should reference them rather than re-deriving methodology locally.
